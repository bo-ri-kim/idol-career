# IDOL LIFE 플레이 피드백 — 2026-11-18 (체감 품질 수정)

상태: 사용자 플레이 검증에서 나온 **미해결 문제**. Codex는 이 문서의 **재현/완료 조건**으로 판정한다. 단순 텍스트 교체, 이벤트 개수 증가 또는 테스트만 통과한 것으로 완료 선언하지 않는다.

## 최상위 목표
> 플레이어가 첫 1분부터 자기 인생의 원인과 결과를 이해하고, 다음에 무슨 일이 생길지 궁금해해야 한다. 수년간 동일한 선택과 문장을 반복하는 클릭 노동을 없앤다.

현재 저장소는 v0.2.6으로 보이는 파일을 확인했다. 이전의 v0.3 콘텐츠 팩은 **일부만 실제 연결**되어 있으며, 본 문서의 피드백은 업로드 이후 실제 플레이에서 나온 것이다. 기존 시뮬레이션·저장·배속·캐릭터 생성 기능을 유지한다.

## 실사용자가 직접 확인한 문제와 수정 요구

### P0-1 학생 상태의 '집에서 온 연락'
- 현상: 산업 진입 전 학생인데 가족과 떨어져 사는 듯한 '집에서 온 연락' 소식 출력.
- 코드 확인: js/events.js 의 family 템플릿 stages에 student/auditioning 포함.
- 수정: 이 표현은 숙소/합숙/독립 거주 상태 등 물리적으로 떨어져 있을 때만. 학생 집 거주 중에는 가정 식사·귀가·부모와 대화 등 일상 소식으로 바꾼다.
- 완료: 집에 사는 학생 100개 시드에서 집에서 온 연락 0회; 연습생이어도 자택 거주 시 동일 로직 적용. 거주 형태가 없다면 이를 추가하거나 부적절한 표현을 제거한다.

### P0-2 관찰되지 않은 SNS 게시물에서 캐스팅
- 현상: 집에서 춤 따라 하고 친구 계정을 보기만 했는데 'SNS 영상 보고 연락'.
- 코드 확인: js/entry.js 의 SNS 발탁은 snsActivity>=10만 검사; 실제 공개 게시 기록이 없음.
- 수정: SNS **소비/연습/게시/공개/조회/확산/스카우트**를 명시적으로 구분. 개인이 영상을 연습한 사실이 자동으로 공개 콘텐츠가 되지 않는다. 실제 게시 이벤트 ID와 공개 범위, 업로드 날짜, 관찰 가능한 조회/확산 근거가 있어야 SNS 발탁 가능.
- 완료: 친구 계정만 보거나 미게시 연습만 한 경우 SNS 발탁 0회. 실제 공개 게시 + 충분한 확산의 근거가 있으면 일정 확률로 연락. 출처 영상/행동을 소식에 명시.

### P0-3 학교 동아리/방과후 활동 부재
- 학생이 음악/댄스/밴드/공연/영상 동아리 또는 방과후 활동에 자발적으로 참여하는 기회를 추가한다.
- 가입→합동 연습→교내 공연→거리 공연/영상 게시→관객/기획사 접점→심사 경로를 구축한다.
- 모든 동아리가 캐스팅으로 이어지지는 않음; 공연·영상·친구 관계만으로 종료 가능. 학업/가정/학생 생활 흐름도 유지.
- 완료: 최소 3개 서로 다른 학생 진입 체인이 실제 시뮬레이션 상태와 기록으로 연결되고, 활동을 하지 않으면 관련 후속 사건이 발생하지 않음.

### P0-4 연습생 갈등이 동일 인물/동일 파트로 고착
- 현상: 새 연습생 '견제' 선택 → 파트 겹침 문제가 여러 해 반복.
- 수정: '견제'는 관계 분포/경쟁심에 영향을 주는 요인이지 영구적인 '파트 분쟁 고정 플래그'가 아님.
- 갈등에 원인(파트·평가·연습 공간·팀워크·행사·사생활·매니저 소통 등), 대상 후보군(신규/기존/친한/무관), 종료 조건(대화·조정·프로젝트 종료)을 부여.
- 한 인물이 갈등 대상으로 계속 등장하지 않게 사건별 인물·원인 쿨다운. 친한 사람과도 갈등 가능, 경쟁자와도 협력 가능. **갈등이 전혀 없을 기간도 유효**.
- 완료: 100 시드 중 관계 선택별 실제 갈등 비율과 대상 분포 기록; '견제'가 필연적 반복 파트 갈등을 만들지 않음. 동일 분쟁 반복 0(후속 아크는 명확히 연결).

### P0-5 데뷔가 한 줄 소식
- 현상: 첫 데뷔라는 핵심 성취가 눈에 띄지 않음.
- 수정: 최초 데뷔 확정(실제 stage 전환 완료) 순간 시간을 멈추고 **전용 축하 모달**을 보여준다. 큰 타이포, 그룹명/포지션/소속사/데뷔 날짜, 축하 문구 여러 변형, 새 커리어 상태 안내. 확인 시 게임 자동 진행 재개.
- 일반 선택팝업과 다른 시각적 위계. 첫 데뷔를 중복 축하하지 말고 저장·이어하기·배속/스킵에서 정확히 한번만.
- 완료: 첫 데뷔 성공 10개 시드에서 10/10 전용 축하 연출, 데뷔 실패 0, 복귀 후 중복 0, 모바일 360px 동작. 발표와 무대 실제 수행을 구분할 수 있다면 '데뷔 확정/첫 무대'도 명확히 구분.

### P0-6 중요 결정 종류 부족, 현실적 권한 위반
- 현상: 2~3년 뒤 '파트 겹침/다음 작품 방향/계약 갱신'만 반복.
- 코드 확인: js/events.js의 comeback은 플레이어가 '새로운 콘셉트에 투자'하도록 선택시키고 있음.
- 수정: 회사나 A&R이 실제 콘셉트와 제작 계획을 결정. 신인은 그 콘셉트를 **어떻게 소화할지**(보컬 집중, 안무 집중, 캐릭터/무대 표현, 팀워크/파트 조율, 피로 관리 등)를 선택. 회사 자율성/경력/제작 참여 권한이 실제 존재할 때만 콘셉트 제안이나 협상 허용.
- 계약 갱신은 실제 계약 종료/재협상 사유에만 연결. 일정 주기 자동 '다음 인생' 질문 금지.
- 중요 결정 종류를 단순 문장 교체가 아니라 상황별 **서로 다른 영향 시스템**으로 확장한다(방송/팬덤/관계/안전/휴식/개인활동/해외활동 등).
- 완료: 임의 3년 활동 중 동일 결정 템플릿의 무의미한 반복 없음. 회사가 정한 콘셉트가 화면에 먼저 제시됨. 계약 만료 이벤트 ID 없이 계약 갱신 금지.

### P0-7 6년 12개 앨범의 불명확성
- 문제는 숫자 자체보다 `releaseSerial++` 중심의 작품 수 증가, 유형/실제 곡/활동의 부재.
- 자료 근거: TXT 2024년 미니 6집/7집 두 번, Stray Kids 2025년 정규·테이프 앨범·디지털 싱글 발매 사례. 6년 12건은 가능하지만 **12개 정규앨범이라면 전혀 다른 이야기**.
- 정규 / 미니(EP) / 싱글 앨범 / 디지털 싱글 / 리패키지 / OST / 협업곡 / 솔로 프로젝트를 구분.
- 각각 별도 releaseId, 그룹/솔로 귀속, 곡 수, 준비 기간, 홍보 기간, 비용, 발매일/상태, 반응, 차트/판매 존재 여부.
- 월별 일정/투어/부상/자금/계약/멤버 가용성에 따라 프로젝트 보류·취소·연기 가능. 가짜 차트 순위 생성 금지.
- 완료: '12개 음반'이 유형별로 설명 가능하며 그룹 정식 작품/개인 작업/리패키지를 중복 계산하지 않음. 상세는 docs/MUSIC_RELEASE_MODEL.md.

### P1-8 7년간 거의 동일한 소식
- 사건이 없는데도 대화 소재만 바뀌는 '대량의 비슷한 문장' 해결 불가.
- 시대·커리어·인물·회사·팬덤·곡·현재 프로젝트에 따라 **활성 이벤트 풀/빈도/주제** 달라져야 한다.
- 1~2개월 단위 준비, 활동기, 공백기, 인기 상승기, 재계약 전후, 전환기 등 서로 다른 계절을 만든다.
- 소식 중복 방지와 별개로 **중요한 새 사실/상황**이 일정 간격으로 쌓이는지 검증.
- 완료: 동일 시드 7년 진행 시 반복 팝업/똑같은 문장 수, 사건 연결률, 분야별 빈도 보고. 5분 단위 사람이 플레이하며 장기 이력의 전환점을 설명할 수 있어야 함.

### P1-9 솔로·배우 이후 세계가 멈춤
- 솔로: 그룹과 다른 팀·제작 방식/개인 팬덤/무대/라이브/음반/방송/광고/협업/사생활/계약 이슈.
- 배우: 오디션→캐스팅→대본 리딩→촬영→편집→방영/개봉→평가→다음 제안, 역할 크기/작품 규모/실패/성공/평판/스태프 관계.
- 전향을 클릭했다는 이유로 다음 작품 선택만 되풀이하지 않는다.
- 완료: 솔로·배우 각 2년 플레이의 **단계별 사건 아크**가 최소 3개씩 가능하며, 발매/작품/홍보/평판 변화가 실제 상태에 남는다.

## 재발 방지 — QA
- 반례(negative tests)를 기본으로 한다: 게시 없음→SNS 발탁 불가 / 부모와 동거→'집에서 온 연락' 불가 / 계약 없음→갱신 불가 / 그룹 없음→멤버 사건 불가 / 데뷔 전→성과·팬덤 불가.
- 중요한 사건 각각 `causeIds`(원인), `actorIds`(관련 인물), `resultIds`(결과), `expiresAt`(종료/쿨다운)를 가능한 범위에서 유지.
- 100개 이상 시드 + 7년 장기 플레이(아직 모든 단계 완전 구현되지 않았다면 현 단계까지).
- 같은 시드·선택에서 ×1 / ×8 / 스킵이 같은 결과를 낼 것.
- Codex는 '실제 코드로 무엇을 구현했는지'와 '플레이어 체감이 여전히 미검증인지' 명확히 분리한다.

## 개발 순서
1. 원인 없는 사건/학생 상태 표현 오류 차단 + QA (이후 작업의 기초).
2. 학생 동아리/공연/SNS 발탁의 원인 체인.
3. 데뷔 전용 축하 UI.
4. 권한에 맞는 중요 결정/반복 갈등 해소.
5. 음반 유형/발매 프로젝트.
6. 분야별(아이돌/솔로/배우) 별개의 중장기 사건과 비활성기 전환점.

한 번에 전부 구현하지 말고 **1~2개 시스템 단위로 개발→테스트→플레이 관찰**한다. 목표는 이벤트 수가 아니라 몰입이다.
