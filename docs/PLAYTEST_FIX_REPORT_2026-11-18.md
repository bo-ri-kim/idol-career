## 세 가지 플레이 가능한 학생 체인

신규 게임 31일째(첫 한 달 일상 이후)에 네 선택을 제공한다. 가입 결정과 공개 여부만 팝업이며 중간 연습과 결과는 자동 소식이다.

1. **댄스**: 가입 → 10일 뒤 첫 합동 연습 → 14일 뒤 두 번째 연습 → 7일 뒤 공개 선택 → 7일 뒤 교내 발표 → 관객 기록이 있으면 학교 공연 심사 후보.
2. **음악**: 동일한 준비 흐름 → 지도자와 함께하는 거리 공연 → 실제 공개 공연과 관객 기록을 계기로 거리 공연 심사 후보.
3. **영상**: 촬영/표현 합동 연습 → 공개/친구 전용/발표 안 함 → 실제 영상 게시 → 공개 영상만 7일 뒤 노출 집계 → 노출 기준을 충족하면 SNS 심사 후보.

미가입은 관련 큐를 만들지 않는다. 발표 거절은 배운 실력을 남기고 종료한다. 친구 전용은 외부 관객/노출을 만들지 않는다. 공개 활동을 해도 연락 추첨·심사 합격은 별도 확률이다. 기존 공개 오디션·길거리·지인·서바이벌도 유지한다. 먼저 직접 지원하면 학교 활동은 심사 중 연습까지만 이어갈 수 있고, 공개 선택은 학생으로 돌아올 때까지 기다린다. 소속사 계약/종료 시 남은 학생 활동은 종료한다.

## 인과·데이터·저장

- studentLife.activity: 활동 ID, 종류, 상태, 가입 사건 ID, 연습 사건 ID 목록, 공개 범위.
- studentLife.posts: post ID, 공개 범위, 게시일/게시 사건 ID, 활동 ID, 조회 수, 해당 post의 노출 기록, 연락 후보 만료일.
- studentLife.performances: 공연 ID, 학교/거리 유형, 공연일/사건 ID, 관객 수, 활동 ID, 선행 연습 ID, 연락 후보 만료일.
- studentLife.actions: 열람·개인 연습·초안·가입·연습·공연·게시·노출을 구분한 사건 참조. 비공개 행동으로 post나 조회를 만들지 않는다.
- 관련 타임라인에 causeIds, actorIds, resultIds를 남기고 부모 사건의 resultIds도 연결한다. 제안에는 sourceId와 노출/공연 causeId, 만료 시점이 붙는다. 조회/관객은 해당 실제 생성 사건에 숫자를 기록한다.
- 조회와 관객은 **게임 안의 확률 시뮬레이션 수치**이며 외부 플랫폼 실측값이 아니다. 실제 API를 조회했다고 표현하지 않는다. 노출 없이 임의 값을 채우지 않고 공개 활동 뒤에만 계산한다.
- 새 연락 후보는 공개 후 180일간. 기간 전에 시작한 심사는 원본 이력을 보존해 완료할 수 있다. 수락 후에도 sourceId가 심사 이력에 남는다.
- 스키마 4의 기존 저장을 유지한다. 구버전 snsActivity/옛 문구에서 게시물과 노출을 소급 생성하지 않는다. 아직 무소속인 구버전의 근거 없는 SNS/공연 대기 제안·심사만 보류하고 새 기회를 예약한다. 이미 계약/데뷔한 과거 경력과 타임라인은 되돌리지 않는다.
