# v0.2.4 세계 및 관계 상태

## 기존 구조 분석과 변경

`state.js`의 한 상태 객체와 저장을 그대로 사용한다. `engine.js`는 일별·월말 계산, 상태 전환, 예약 사건과 타임라인을 담당한다. `events.js`는 조건과 선택 데이터, `entry.js`는 학생 진입 경로, `clock.js`는 실시간·배속·비활성 처리를 담당한다. 별도 세계 시계나 두 번째 저장소는 만들지 않았다.

## 데이터

| 위치 | 내용 |
| --- | --- |
| 루트 상태 | 플레이어 기본 정보·능력치·커리어·현재 소속/그룹/프로젝트/계약 ID·타임라인·관계 |

| world.projects | ID, 기수, 단계, 소속사, 참가·선발 인물, 정원, 평가, 협력 성과, 상태 |

플레이어는 명시적 `player` ID로 명단에 참여한다. 인물마다 중복 관계 객체를 두지 않고 플레이어 관계를 한 곳에 저장한다. 사건의 `personIds`와 같은 타임라인 사건 ID를 사용해 인물·관계 이력을 연결한다. 종료된 프로젝트, 탈퇴한 그룹, 종료 계약도 레지스트리에 남는다.

## 첫 만남 체인

계약 후 정규 연습생 프로젝트 시작 → 12일 뒤 신규 인물 합류 → 자동 정지와 3개 선택 → 25일 뒤 같은 ID의 후속 사건. 프로그램 후보 직행·학생 상태에서는 신규 연습생 체인이 시작되지 않는다.

| 선택 | 친밀도 | 신뢰 | 경쟁 | 추가 |
| --- | --- | --- | --- | --- |
| 친해지기 | +20 | +12 | +3 | 접근 이력 |
| 견제하기 | -4 | -10 | +25 | 갈등 이력 |
| 거리 두기 | 0 | +1 | +1 | 접근 이력 |

후속 협력 확률은 `0.16 + 신뢰×0.006 - 경쟁×0.003 + 협력적 성격 0.14 - 야심 성격 0.12`이며 5~80%로 제한한다. 경쟁 확률은 `0.12 + 경쟁×0.006 + 야심 0.16 + 갈등 존재 0.08`을 8~80%로 제한하고 남은 확률을 넘지 않게 한다. 나머지는 친밀도 30 이상이면 관계의 부담, 아니면 나란히 연습하는 소식이다. 친밀도만으로 좋은 결과가 보장되지 않는다.

협력은 서로의 연습 성과와 신뢰·프로젝트 협력에, 경쟁은 실력·멘탈·갈등에 영향을 준다. 관계 평가의 데뷔 확률 영향은 ±4% 이내이며 협력 성과도 작게 반영한다. 기존 능력·프로젝트 평가가 중심이다.

## 상태와 저장

현재 소속 ID가 실제 소속사로 해석되어야 내부 사건이 가능하다. 그룹 사건은 실제 그룹과 데뷔가 필요하다. 전향 시 플레이어의 현재 그룹 참여를 종료하고 이력을 남긴다. 은퇴 시 계약과 예약·시간 진행을 종료한다. 모든 예약은 실행 시 현재 단계를 재검사한다.

스키마 4는 세계·관계·사건 참조를 함께 저장한다. 인물 재생성 없이 같은 ID를 복원한다. 누락된 인물, 잘못된 명단·현재 소속, 끊어진 관계·갈등·사건 참조는 거부하고 새 시작 안내를 표시한다. 구버전 저장은 명시적 초기화 전까지 보존한다.

## 검증과 범위

`npm test`: 기존 23개와 세계 테스트 10개, 총 33개. 100개 시드의 기존 커리어 완주, 글로벌 스타·실패 후 전향·자발적 은퇴, 상태별 사건 격리, 같은 인물 후속 사건, 세 접근 선택, 관계별 다른 확률·결과, 불리한 높은 친밀도, 저장·배속 동일 미래, 그룹 탈퇴와 종료 계약 보존을 확인한다.

브라우저에서도 학생 → 공개 오디션 → 계약 → 지후 합류 → 새로고침·이어하기 → 친해지기 → 25일 뒤 같은 지후의 협력 소식 → 최종 평가를 확인했다.

이번 단계는 관계 체인 한 개와 기존 동료 소식 재사용이 중심이다. 세계는 플레이어와 같은 게임 시간에 유지되지만 모든 NPC가 독립적으로 직업·계약을 바꾸는 시뮬레이션은 아직 아니다. 복잡한 음악·팬덤 경제나 대규모 이벤트 확장은 포함하지 않는다.
