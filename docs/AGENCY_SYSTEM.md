# IDOL LIFE — 소속사 시스템 기획

상태: **설계 제안 / 아직 구현 완료 아님**. 현재 저장소의 world.agencies 및 계약 객체와 대응해 단계적으로 연결한다.

## 원칙
- 학생은 무소속으로 시작한다.
- 기획사에 먼저 지원하거나, 합법적 경로로 제안을 받을 수 있다. 수락이 곧 데뷔는 아니다.
- 회사 규모는 절대적인 성공 수치가 아니라 **자원·경쟁·노선·계약·위기 대응의 복합 특성**이다.
- 기본 유형은 대형 / 중견 / 신생 / 전문 레이블. 각 회사에 고유 이름과 ID, 규모와 별도 랜덤 특성을 준다.
- 한 플레이에서 복수 회사가 존재하며, 각각 다른 상황과 데뷔 프로젝트를 운영한다.
- 회사 A에서 발생한 프로젝트가 회사 B에도 똑같이 발생하는 식의 범용 뉴스는 피한다.

## 소속사 속성 (후보 필드)
| 속성 | 설명 | 영향을 주는 시스템 |
| --- | --- | --- |
| scale | 대형/중견/신생/전문 레이블 | 자원 한계, 경쟁자 수, 대중의 초기 주목 |
| capital | 자금 안정성 | 프로젝트 지속·연기·취소·위기 |
| trainingQuality | 보컬/댄스/랩·교육 수준 | 성장 속도 |
| debutCompetition | 소속 경쟁자, 프로젝트 정원 | 데뷔조 경쟁·선발 |
| marketingPower | 홍보·유통·네트워크 | 데뷔 초기 노출·음반 반응 |
| creativeAutonomy | 아티스트 참여 허용 | 콘셉트 해석·창작 참여 선택 |
| artistCare | 휴식·건강 보호/지원 | 피로 회복·위기 대응 |
| managementStyle | 통제형/협업형/실험형 등 | 갈등·협의·재계약 |
| financialTransparency | 정산의 명확성 | 수익 신뢰·분쟁 |
| debutProjects | 프로젝트 ID 목록 | 실제 데뷔 계획과 일정 |

위 값과 효과는 고정 공식이 아닌 밸런싱 가설. 대형=무조건 좋음, 신생=무조건 나쁨은 금지.

## 제안/계약 흐름
1. 학생의 능력·관심·SNS·학교 이벤트 등에 따라 지원/스카우트 기회가 생긴다.
2. 접촉의 진위를 확인하고 보호자 동반 등 안전 절차를 거친다(미성년).
3. 심사 결과가 나오고, 합격이면 회사 정보·프로젝트 상태·조건을 공개한다.
4. 여러 제안을 받을 수도 있고 보류·거절도 가능하다. 제안에는 유효 기간이 있다.
5. 계약하면 trainee 또는 조건에 따른 후보 프로젝트로 이동한다.
6. 회사의 자금·운영·실제 프로젝트 변화가 커리어 소식과 선택에 지속 반영된다.

## 의미 있는 회사 차이 예시
- 대형: 더 나은 훈련과 초기 홍보 가능성, 하지만 후보자가 많고 내부 선발 기준이 높음.
- 중견: 일정 자원과 프로젝트 경험, 특정 팀에 자원 집중으로 변동성.
- 신생: 작은 프로젝트·새로운 전략, 빠른 기회도 있지만 자금·인력 불확실성.
- 전문 레이블: 장르 적합성·자율성이 강점일 수 있으나 시장이 제한적.

## 사건 예시와 실제 영향
- 투자 유치/철회 → 프로젝트 일정·예산 조정 → 데뷔 연기 또는 홍보 확대.
- A&R 교체 → 콘셉트 및 연습 우선순위 변화 → 사용자 대응 방침 선택.
- 경쟁 그룹 우선 데뷔 → 플레이어의 데뷔 대기 기간 증가.
- 매니저 교체 → 일정·안전·소통에 변화 → 팀 신뢰 또는 피로.
- 정산 내역 설명 요구 → 신뢰, 투명성, 계약 재검토 가능성.
- 중견 회사의 대형 협업 제안 → 그룹 노출 상승 기회와 회사 결정권 갈등.

## 개발 순서
1. world.agencies 현 구조 감사를 먼저 수행한다.
2. 실제 존재하는 회사와 가상 특성 사이에 최소 필드 매핑을 구성한다.
3. 계약 제안 시 규모+운영 특성+진행 프로젝트를 표시한다.
4. 최소 2개의 속성이 훈련·선발·홍보·정산 중 실제 계산에 반영되게 한다.
5. 같은 시드에서 다른 회사 선택이 최소 하나의 후속 사건/커리어 결과 분포를 바꾸는지 검증한다.

## 아직 결정되지 않은 것
- 시작 시 회사 총수(임시 목표 10~20개, 성능 테스트 후 조절)
- 상세 계약 기간·수익 배분 수식 및 위약금 표현
- 회사별 창작 권한 계산
- 실존 소속사 사용 여부(현재는 허구의 회사 권장)
