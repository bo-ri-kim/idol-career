# v0.2.6 — NEXT 소식 다양성 적용 보고

## 가져온 기준과 기존 분석

2026-11-18 main `d996b044759724705e516a5f4719494eed2d2c24`의 AGENTS.md, docs 및 data/event-pack-v03을 가져와 확인했다. 기존 로컬 실행 파일은 이 main과 Git blob 해시가 동일했고 새 문서·데이터를 그대로 추가했다. 이 작업 디렉터리는 기존 파일이 전부 untracked이며 remote가 없는 상태여서 충돌 가능성이 있는 git pull/초기화를 하지 않고 GitHub 커넥터로 고정 리비전을 읽어 비교했다.

엔진은 단일 루트 상태, 저장 가능한 난수, 일 단위 계산/월말 정산, 직업 epoch가 있는 예약 큐, 팝업 대기 결정, 최신순 타임라인 구조다. world의 고유 ID와 관계도 이미 존재한다. 기존 39개 테스트는 변경 전 통과했다. 문제는 일반 소식 30개(무작위 29개+예약용 join 1개) 중 일부를 35일 후 재사용하고, 주제 가중치와 소속·계약의 상세 검증이 없었던 점이다.

## 실제 구현

- 원본 300개 일반 소식 중 **48개**: 학생 16, 연습생/후보 16, 그룹/작품 준비 16. 기존 무작위 소식 29개를 합쳐 현재 선택 풀 77개다. 원본 텍스트는 보존하고 인물 관계 소식 8개는 실제 인물 ID로 문구를 조정했다. 제목 48개도 사건별로 구별했다.
- 일반 소식 ID는 한 커리어에 한 번. `seen` 구버전 기록도 기발생으로 인정한다. 같은 주제 연속 금지, 주제 간격 14일, 최근 8개 주제의 빈도에 따른 가중치 감소, 동일 문장 필터를 적용한다.
- 후보 조건 불일치는 `newsMemory.rejected`에 이유를 저장한다. 선정 결과는 실제 소속·그룹·프로젝트·인물 ID 및 eventId/topic과 함께 타임라인에 남긴다.
- 일반 소식은 자동으로 지나가며 중요 결정만 정지한다. 기존 성장·경제·관계·프로젝트·배속·종료 흐름을 유지한다. 새 풍경 소식에 관련 없는 능력·재화 효과를 붙이지 않았다.
- 검토한 원본을 `scripts/build-event-pack.mjs`로 정적 JS에 생성한다. 실행 중 외부 호출·대규모 JSON 일괄 활성화가 없다. `npm run check:content`로 원본과 생성물 일치를 확인한다.
- 콘텐츠 팩의 **동료에서 라이벌로 1개 아크/4단계**를 기존 합류 → 확률적 재회 → 프로젝트 인원 축소 → 최종 평가에 연결했다. 기존 실제 날짜와 선택 효과를 재사용하고 같은 personId/agencyId/projectId와 선행 단계를 검사한다. 다른 기수로 바뀌면 이어붙이지 않는다. 협력·합격 고정 문구는 그대로 실행하지 않고 기존 확률 결과를 쓴다. 새로 독립적인 아크 엔진을 만든 것은 아니다.

## 필드 매핑과 보수적 제한

| 원본 | 현재 매핑 / 제한 |
| --- | --- |
| phase_in | 실제 student/trainee/debut_candidate/idol/solo만 사용. rookie/veteran/hiatus를 임의로 새 상태로 만들지 않음 |
| player.schoolEnrolled | 새 학적을 지어내지 않고 18세 이하 student의 짧은 프롤로그로 제한 |
| player.agencyId | s.agency → world.agencies 및 활성 계약 ID 확인 |
| world.debutProjectActive | 실제 현재 프로젝트와 준비 상태. 동료는 s.rivals의 실제 인물 |
| world.activeMusicProject | 현재 epoch의 아직 발매되지 않은 release 예약. 곡 ID나 차트를 지어내지 않음 |
| group/member | 실제 활성 그룹과 멤버 명단. 선배는 계산한 나이, 춤 피드백은 실제 댄스 실력, 파트 갈등은 경쟁 수치 필요 |
| max_occurrences | 일반 소식은 평생 1회. 원본 개별 간격 대신 더 보수적인 1회 제한과 분야별 간격 사용 |
| weight/tags/category | 검토된 주제 매핑과 시드 가중 추첨. 화면 분류와 주제 분류를 분리 |

곡 카탈로그, 차트, 투어, 판매량, 정산, 병역 자격은 대체 수치를 생성하지 않는다. 원본에 조건이 빠진 문장도 그대로 활성화하지 않았다. 예: 오디션 결과 연기 소식은 실제 결과 날짜를 바꾸지 않으면 모순이므로 이번에 제외했다.

## 한계와 다음 후보

기존 저장의 과거 중복 기록은 삭제하지 않는다. 앞으로의 기발생 ID만 막는다. 일반 소식 후보가 소진되면 정직한 기존 월말 성장/평가/정산 기록만 계속되므로 장기 플레이에서는 일반 소식 밀도가 줄어든다. 이는 같은 문장으로 채우는 대신 남겨 둔 콘텐츠 확장 과제다. 일부 추상적인 월말 수익 모델은 기존 그대로이며 정교한 실제 정산을 구현했다는 뜻이 아니다.

NEXT 전체 라이브러리 통합 완료로 보지 않는다. 다음 후보는 미연결 일반 소식의 상태 전제 검토와 실제 계산 가능한 월말 템플릿의 소규모 연결이다. 다른 대규모 시스템 단계로 자동 진입하지 않는다.
