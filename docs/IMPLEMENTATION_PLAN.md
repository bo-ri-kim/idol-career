## NEXT — ACT 1 / 01 소속사 계약 제안·적합성 (구현 대기)

**기준 문서**: [ACT 1 설계](ACT1_STORY_DESIGN.md) · [소속사 시스템](AGENCY_SYSTEM.md) · [v0.2.8 플레이 피드백](PLAYTEST_FEEDBACK_2026-11-18.md) · AGENTS.md.

**사용자 피드백:** "어느 회사인지도 모르고 계약하게 한다. 회사 규모·장점·회사와 나의 기대가 맞아야 계약할 수 있어야 한다."

### 이번 작업 범위
1. 현 코드에서 **심사 합격 → 제안 → 계약 수락** 흐름과 `signContract(s,route)`를 감사한다. 현재는 **수락한 뒤** 회사를 랜덤 배정하고 있어 계약 정보가 실제 회사와 무관하다.
2. 심사 합격 **시점**에 실제 회사 `agencyId`가 정해진 `offerId`를 만든다. 제안·결정·계약·기록·저장/불러오기가 **동일한 회사 ID**를 참조해야 한다. 프로그램/서바이벌은 해당 맥락을 별도로 유지.
3. 계약 결정 UI에서 **회사명·대형/중견/소형 등 규모·성향·보유 자원·훈련 장점·회사 기대·프로젝트 현황·알려진 계약 조건/불확실성**을 보여 준다. 없는 정보는 "미확인"으로 표시한다.
4. 플레이어가 중시하는 것(빠른 데뷔/집중 교육/창작 참여/안정적 지원)과 회사가 원하는 것(기량/팀워크/표현력 등)을 비교해, 왜 맞거나 맞지 않는지 설명한다. 미지의 항목은 과신하지 않는다.
5. 소속사 선택이 **훈련·평가/경쟁·초기 기회 중 적어도 두 개의 기존 계산 결과**에 차이를 낳게 한다. 회사 규모만으로 승패 확정 금지. 현재 존재하는 회사 3~4개부터 검증; 다수 회사 생성은 이번 범위 아님.
6. 수락/거절 외에 조건 확인 또는 보호자 상담/보류가 **실제로 가능**하도록 하되 미성년자 계약 안전을 해치지 않는다. 선택지는 실제 엔진 동작이 있어야 한다.
7. 기존 저장 파일을 유지·이관하거나 호환이 불가능하면 정확한 사유를 사용자에게 설명한다. 임의 저장 초기화 금지.

### 완료 검증

- `npm test` 및 시드 시뮬레이션 실행. 기존 자동 진행·중요 결정 복귀 기능 유지.
