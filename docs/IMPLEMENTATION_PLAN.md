목표: 기존 몇 개의 '연습했다/밥 먹었다/동료를 만났다' 소식 반복을 줄이고, 학생/연습생/아이돌의 상황에 맞는 실제 소식이 다양하게 나오게 한다.
1. 기존 js/events.js, js/engine.js의 일반 소식 선정/쿨다운 및 이벤트 풀 진단.
2. data/ 콘텐츠 팩을 확인하고 실제 코드 필드와 커리어 단계를 매핑. 지원하지 않는 타입은 비활성화 및 이유 보고.
3. **첫 작업 범위는 일반 소식 조건 검증 + 중복 방지 + 소규모 대표 이벤트 통합**으로 제한. 게임을 고장내며 440개를 무조건 활성화하지 않는다.
4. 가능하다면 5개 연결 사건(축제/연습생 관계/데뷔/직캠/역주행) 중 현 코드 상태로 검증 가능한 1~2개를 우선 연결.
5. npm test 및 최소 100개 시드 QA로 학생 상태 침범, 미데뷔 차트, 같은 소식 반복, 가짜 계산 수치, 부자연스러운 사건 체인 문제 확인.
6. 최종에 **실제로 연결한 소식 수**, 로드 불가능한 이벤트, 차기 시스템 의존성을 구분해 보고.

**중요:** 이 작업은 현재 코드 분석과 테스트를 먼저 한다. 사용자가 다른 범위를 지정하면 우선순위를 재조정한다. GitHub 문서가 바뀌었다는 사실만으로 구현을 완료했다고 선언하면 안 된다.

### 이번 1회 작업 범위 (P0-1, P0-2, P0-3만)
1. 학생이 집에 살고 있는데 '집에서 온 연락'이 나오는 사건의 단계/거주 조건을 수정한다. 다른 연습생/소속사 생활과 구분한다.

3. 학교 방과후/동아리 활동을 학생 상태에 최소 2종 구현한다. 활동→연습→공연/공개 게시→발탁 가능성으로 연결하며, 각 단계에 기록 가능한 원인 ID를 남긴다. 이미 학교 축제 루트가 있다면 재사용한다.
4. 원인 없는 사건 0건을 검증하는 반례 테스트를 추가한다. 배속·스킵·저장 복원에도 적용.
5. 기존 플레이 경로 및 엔딩 정상 유지, npm test 및 최소 100 시드 경로 점검. 완료 보고에서 **변경한 사건과 재현 조건**을 보여준다.

## 현재 코드와 합의한 기획 사이 확인할 차이
- 시간 속도: config.js 현재 ×1 1년≈240초, 기획 검증값 ×1 1년≈60초. UI 밀도 테스트 후 조정 필요.
- 현재 엔딩: README 기준 45세 자동 정리. 기획에서는 특정 나이 강제 종료보다 커리어 맥락과 자발적 은퇴를 선호.
- 실제 콘텐츠 풀: README 기준 일반 소식 30개 수준. 440개 라이브러리는 자동 통합되지 않았다.
- 현재 후속 인간관계: README에는 반복 관계 사건+평가 영향이 명시돼 있지만, 플레이어는 실질적 변화 체감이 약하다고 평가. 수치 변화 설명·다양한 후속 선택·커리어 연결을 실제 게임에서 확인.
- 소속사: world.agencies 레지스트리가 있지만 다양한 회사 선택에 따른 체감 효과는 추가 점검 필요.
- 작품 콘셉트: 신인 플레이어가 전체 작품 방향을 결정하는 방식은 수정 대상.
