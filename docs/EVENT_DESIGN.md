# IDOL LIFE — 소식 및 사건 시스템

상태: 기획 + 콘텐츠 적용 계약. 이벤트 JSON은 엔진을 대체하지 않으며 실제 코드 상태와 매핑이 필요하다.

## 4개 사건 유형
1. **일반 소식(ambient)**: 훈련, 친구, 학교, 활동, 소속사, 멤버, 방송, 팬 등. 시간은 멈추지 않는다.
2. **상태 기반 소식(state-derived)**: 실제 성장·평가 순위·차트·판매·수익·팬덤 변화에서 생성. 데이터가 없으면 출력하지 않는다.
3. **연속 사건(story arc)**: 원인→경과→결과가 시간에 걸쳐 이어지는 예약 사건 체인. 캐릭터·곡·회사 ID 및 선행 단계가 유지되어야 한다.
4. **중요 결정(decision)**: 실제로 플레이어가 선택할 수 있는 행동. 시계 자동 정지, 결정 후 진행 재개.

## 다양성/중복 방지 규칙
- 기본적으로 일반 소식 ID는 커리어당 한 번만 발생한다.
- 카테고리별 쿨다운, 같은 의미의 문장 연속 노출 방지, 최근 주제 다양성 가중치를 적용한다.
- 플레이어가 관찰하는 소식은 체감상 반복되지 않아야 하지만, **서로 다른 사건 없이 단순한 문장 변형만 계속 생성하는 방식은 금지**한다.
- 사건 시작 전 커리어 단계, 계약·그룹·곡·프로젝트, 연령·자격, 이전 사건 조건을 검증한다.
- 사건 수와 화면 노출 속도를 분리한다. 활동기는 밀도가 높지만 한 달 5초인 목표 속도에 다 표시할 필요는 없다.
- 소식 내용과 상태가 충돌하면 소식을 버리고 진단 로그에 이유를 기록한다.

## 지속되는 인물/선택
- 이름 있는 인물에는 고유 ID를 부여한다. 같은 인물은 같은 이름·나이·이력과 연결되어야 한다.
- 선택은 실제 상태, 후속 이벤트 가중치, 일정, 재화, 평가 중 적어도 하나에 효과를 준다. 문구만 달라지는 선택은 미완료로 보고한다.
- 친구가 되면 협력 연습과 팀 평가에 이득이 될 수 있지만 경쟁과 갈등이 없어지는 것은 아니다.
- 견제는 동기부여나 경쟁 성장의 이득이 있을 수 있지만 단체 평가 비용을 만들 수 있다.
- 시간이 지난 뒤의 결과는 확률과 변화된 상황을 반영하며 무조건 확정하지 않는다.
- 긴급 상황·사고는 피해의 책임을 플레이어에게 돌리지 않는다.

## 소식 분야
- 학생: 학교·학업·동아리·축제·친구·가족·취미·SNS·우연한 기회.
- 진입: 지원, 길거리 캐스팅, 연락 검증, 심사, 계약 비교, 보호자 협의.
- 연습생: 평가, 경쟁, 합동 연습, 이탈, 데뷔조, 트레이너, 가족, 피로.
- 그룹: 포지션(리더/센터/보컬/댄스/랩/비주얼 등), 파트 분배, 멤버 갈등, 팀워크.
- 음악: 회사가 정한 콘셉트, 준비, 녹음, 발매, 음원·음반·방송, 첫 1위, 시상식.
- 성장: SNS/직캠/챌린지, 역주행, 팬덤, 해외, 광고, 앰배서더, 예능, 투어.
- 위기: 사고, 부상, 질병, 악성 루머, 스토킹, 사생활 침해, 스태프·매니저·대표 갈등.
- 후기: 정산·재계약·이적·병역 해당자 공백·솔로/배우 전향·해체·재결합·은퇴.

## 이벤트 조건 샘플
- 신규 연습생 → player.phase=trainee + agencyId + 실제 회사 프로젝트; 생성한 NPC ID를 저장.
- 음원 역주행 → 이미 발매한 곡 + 시간이 지난 작품 + 유효한 관심/영상 신호 + 낮은 기본 확률; 차트 변동은 실제 계산.
- 열애 제안 → 아이돌 관련 인물이 실제 존재 + 상호 관계 + 적절한 커리어 단계; 수락/거절은 도덕적 정답이 아님.
- 차트 순위 → 실제 songId/releaseId와 차트 집계 로직이 있을 때만.
- 병역 → 국적/실제 적용 대상 및 병역 상태로만 판단. 단순 성별 필터 금지.
- 은퇴/전향 → 계약 만료·부상·그룹 활동 중단·새로운 기회 등의 맥락, 또는 플레이어의 자발적 종료 요청.

## 주요 성취의 연출
- 데뷔 확정: 그룹명·포지션·데뷔 날짜·첫 활동 공개; 별도 성취 연출을 주되 팝업 남발 금지.
- 첫 음악방송 1위/첫 대상 등: 타임라인의 특별한 카드/간단한 연출.
- 발매곡/개인 인지도와 실제 수입은 별개의 모델로 관리.

## 콘텐츠 팩
별도 제공된 v0.3 라이브러리 구성: 일반 소식 300, 결정 30, 연속 시나리오 19개(76개 단계), 상태 기반 34 = 콘텐츠 단위 총 440.
팩의 phase 명칭과 속성은 현재 코드와 일치하지 않을 수 있다. 오리지널 이벤트를 로드하기 전에 반드시 docs/event-conditions.md와 실제 코드에서 조건 매핑을 검증한다.
- 1차: 실제 가능한 일반 소식, 중복/조건 검증.
- 2차: 계산된 데이터 기반 소식.
- 3차: 축제→오디션, 새 연습생 관계, 데뷔 주간, 직캠 확산, 역주행 등 연결 아크.
- 4차: 각 선택의 실제 효과 및 나머지 아크 검증.

## QA
- 서로 다른 100개 시드로 첫해 고유 소식 비율과 조건 위반을 기록한다.
- 동일 사건 ID 중복=0(명시적 반복 예외 제외).
- 학생/무소속/미데뷔/무곡 등에서 불가능한 사건=0.
- 동일 시드·선택에서 배속별 상태=동일.
- 진입 실패, 그룹 무명, 바이럴, 전향 등 여러 경로를 재현한다.
- 이벤트 선택이 실제 상태를 바꾸고 몇 주~몇 달 뒤에도 영향이 남는지 테스트한다.
