# 다음 무대 — IDOL LIFE v0.2.1

시간이 자동으로 흐르고, 커리어 소식이 쌓이며, 중요한 결정에서 멈추는 한국어 데스크톱 웹게임 프로토타입입니다. HTML·CSS·Vanilla JavaScript로 만들었으며 외부 API, 유료 서비스, 백엔드, 외부 이미지, 설치 의존성이 없습니다.

플레이: https://bo-ri-kim.github.io/idol-career/

## v0.2.1 읽기 편의 개선

- 데스크톱에서는 넓은 커리어 타임라인과 오른쪽 상태·방침·소속 패널을 동시에 봅니다. 작은 화면에서는 한 열로 정리합니다.
- 기본 시간은 이전보다 4배 느립니다. ×1에서 게임 1년은 현실 약 4분입니다. 사건 수와 일별 계산은 그대로 유지합니다.
- 중요한 결정은 배경을 가리는 중앙 팝업으로 표시하고 시간을 멈춥니다. 선택 전에는 Escape나 배경 클릭으로 사라지지 않으며, 선택하면 팝업이 닫히고 자동 진행을 재개합니다.
- 기존 v0.2 저장은 그대로 이어갈 수 있습니다.

## 실행

프로젝트 폴더에서 실행합니다.

```sh
npm start
# 또는
python3 -m http.server 8080
```

http://localhost:8080 에 접속하세요. ES 모듈을 사용하므로 파일을 직접 더블클릭하는 file:// 방식 대신 정적 서버가 필요합니다. 서버는 파일만 제공하며 게임 상태를 처리하거나 저장하지 않습니다. GitHub Pages에서는 컴퓨터가 꺼져 있어도 외부 모바일 접속이 가능합니다.

## v0.1에서 달라진 구조

기존에는 선택 한 번에 3개월이 흐르고, 결과 확인 후 다음 사건을 눌렀습니다. v0.2에서는 다음 순서로 움직입니다.

1. 실제 경과 시간에 따라 게임 날짜가 하루씩 진행됩니다.
2. 지속 활동 방침이 능력치·체력에 누적되고 일상·소속사·커리어 소식이 자동으로 발생합니다.
3. 월이 바뀌면 훈련 평가, 경쟁 연습생 변화와 월별 정산이 처리됩니다.
4. 중요한 결정이 발생하면 시간이 정지합니다. 선택 기회는 사라지지 않습니다.
5. 선택 결과는 타임라인에 기록되고 시간이 바로 재개됩니다. 결과 확인용 다음 버튼은 없습니다.
6. 오디션 결과·작품 반응 등은 예약된 날짜에 뒤늦게 돌아옵니다.

## 조작

- **시작:** 이름 입력/랜덤, 성별 선택/랜덤. 13~18세, 배경·초기 실력 랜덤. 성별은 실력과 성공 확률에 영향을 주지 않습니다.
- **재생/일시정지:** 게임 시작 시 자동 재생. 일시정지 중에는 날짜·능력치·사건이 변하지 않습니다.
- **배속:** ×1 / ×2 / ×4 / ×8. ×1에서 현실 4분에 게임 365일, 1일 약 0.658초입니다. 실제 달력의 월 길이와 윤년을 따르므로 윤년 한 해는 약 240.66초입니다.
- **다음 결정까지:** 중간 날짜를 하루도 생략하지 않고 빠르게 계산합니다. 최대 732일 안에 결정이 없으면 기록을 남기고 수동 정지합니다. 재생 또는 다시 진행할 수 있습니다.
- **활동 방침:** 준비/연습생/데뷔 준비에서는 보컬·댄스·랩·균형·컨디션 관리. 데뷔 이후에는 작품·팬/방송·균형·컨디션 관리. 즉시 보상이 아닌 시간 누적 효과입니다.
- **소식:** 날짜 오름차순. 기본은 최근 80개이며 이전 소식 더 보기와 주요 소식 필터가 있습니다. 기록은 내부 상태에 모두 남습니다. 과거 기록을 읽는 중에는 스크롤을 강제로 내리지 않고 최신 위치 버튼을 표시합니다.
- **저장:** 약 2초마다, 선택·결정 발생·일시정지·배속/방침 변경·시작 화면 복귀·페이지 이탈 시 저장합니다. 별도 계정 없이 같은 브라우저에서 이어합니다. 닫힌 기간과 비활성 탭의 시간은 진행하지 않습니다.
- **은퇴:** 하단 연예계 은퇴에서 확인 후 결산합니다. 그룹 탈퇴 후 솔로 활동, 아이돌 은퇴 후 배우/제작자 활동은 연예계 은퇴와 다릅니다.

## 사건의 연결

- 오디션·SNS·캐스팅 참여 → 14일 후 합격/불합격 → 합격 시 연습생 계약 결정.
- 계약 → 30일 후 새 그룹 발표 → 80일 후보 선발 → 115일 인원 축소 → 150일 최종 평가 결정.
- 누적 실력, 월말 평가, 경쟁 연습생 점수, 후보 이력, 훈련 기간을 반영 → 도전 후 30일 뒤 데뷔 결과.
- 실패 → 30일 재정비 → 재도전 또는 배우·제작자 전향. 실력은 유지됩니다.
- 음반 방향 선택 → 30일 제작 → 발매 → 14일 뒤 반응 → 다음 활동 기회.
- 연기 배역 선택 → 30일 뒤 결과, 제작 참여 → 60일 뒤 결과.
- 그룹/솔로 활동에서는 정기 계약 갱신·전향 기회가 나옵니다.
- 커리어 전환 시 이전 분야의 예약 사건을 제거하여 소속·활동과 맞지 않는 소식을 방지합니다.

## 소식 빈도와 조정

`js/config.js`의 `newsPerMonth`, 확률 계수, 프로젝트 일정, 활동 방침을 수정할 수 있습니다.

기본 월평균 목표는 준비/연습생 3개, 데뷔 준비 5개, 그룹 6.5개, 솔로 6개, 배우 3.5개, 제작자 3개, 공백/회복 2개입니다. 월말 기록 1개를 제외한 일반 소식은 일별 확률로 발생하며 최소 35일의 템플릿 재사용 간격이 있습니다. 프로젝트·결정·후속 결과는 별도로 더해져 특정 달에는 소식이 몰릴 수 있습니다. 목표 수를 맞추기 위해 사건을 강제로 채우지는 않습니다.

## 상태와 종료 규칙

단일 상태 객체에 날짜, 난수 시드, 시간 누적분, 능력치, 방침, 소속사, 그룹, 경쟁 연습생, 프로젝트, 예약 사건, 대기 결정, 이력과 업적을 저장합니다. 날짜에는 실제 UTC 달력을 사용하므로 기기 시간대나 서머타임에 영향받지 않습니다.

능력치는 0~100, 인기는 0~100이며 순자산은 최소 -5,000만원으로 제한한 가상 경제입니다. 건강이 크게 떨어지면 회복 또는 은퇴를 결정합니다. 회복기에는 훈련/활동 대신 컨디션 관리가 적용됩니다. 27세까지 준비 단계에 남거나 데뷔 실패가 5회 누적되면 전향 선택이 나옵니다. 45세에는 장기 커리어를 마무리하므로 무한 활동은 없습니다.

결산에는 주요 커리어 타임라인, 최고 인기와 시점, 순자산, 데뷔 도전, 창작 경력, 주요 성과, 전향/은퇴 과정과 에필로그가 나옵니다.

## 저장 호환성

v0.2는 `idol-career-v02` 키를 사용합니다. v0.1 저장을 억지로 변환하지 않으며, 기존 데이터만 있으면 새 게임 안내가 나옵니다. 손상됐거나 지원하지 않는 데이터는 이어하기를 막고 새 게임을 허용합니다. 명시적으로 저장 초기화를 고르기 전까지 v0.1 키는 삭제하지 않습니다.

## 미구현 및 플레이 점검 과제

- AI 실시간 스토리 생성, 상세 관계/기획사 경영, 캐릭터 이미지, 정교한 음반 경제는 범위 밖입니다.
- 일반 소식 20종과 결정 12종을 재사용합니다. 장기 플레이에서는 문구가 반복됩니다.
- 경쟁 연습생은 이름과 점수 중심의 간단한 모델입니다. 개별 경쟁자의 생애나 팀 케미스트리는 없습니다.
- 자산, 인기, 계약 비용, 성공 확률은 초기 밸런스입니다. 빠른 성장·안정적인 장기 수익·건강 관리의 난이도를 실제 플레이로 조정해야 합니다.
- 연습생 프로젝트가 5개월 간격으로 너무 빠르게 느껴지는지, ×1/×8에서 기록을 읽을 여유가 있는지 확인이 필요합니다.
- 주요 결정 중에는 방침 변경도 잠깐 잠급니다. 과거 기록을 읽는 동안 결정이 화면 위에 나타나므로 고정 시간 제어의 ‘결정 대기’ 표시를 확인하세요.
- 오프라인 진행, 자동 의사결정, 여러 저장 슬롯, 클라우드 저장 동기화, 저장 내보내기는 없습니다.
- 최장 32년 내외의 모든 기록을 localStorage에 보관합니다. 저장 공간이 부족하면 경고가 나오며 현재 플레이는 계속되지만 다음 재접속은 보장되지 않습니다.
